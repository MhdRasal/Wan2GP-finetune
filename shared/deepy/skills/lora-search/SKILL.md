# LoRA search and install

When a style, subject, character or effect is beyond what the base model renders well, look for a LoRA before settling for prompt words.

1. **The model first.** LoRAs are made for one base model. Use the model the user named or the one you will generate with: `model_type` accepts its type or its name ("Wan 2.2 text to video"). To see the types behind a name, use `wangp_models` action `lookup` (`{"query": "<name>"}`: type, name and output only), not `wangp_models(query=...)`, whose full records serve generation settings. Close variants of a family share LoRAs (the Qwen Image Edit models share one folder; Qwen Image 2.1 is a different family).
2. **One search.** `lora_search` with a short `query` (the theme in two or three words: `pixel art`, `manga girl`, `film grain`) and the `model_type`. It searches Civitai and Hugging Face (`source` narrows it when the user names a site) and returns only the LoRAs made for that model, best first: name and tags matching the query, then popularity. Each result gives `id`, `trigger_words`, `size_mb`, downloads and `page_url`; `other_base_models` only counts the matches for other models. Pages hold six results: ask `next_page` only when the first page lacks a good candidate (later pages match less, and the search stops offering pages once the rest only mention the theme in passing); a second wording (anime instead of manga) is worth one more search, not five. When two wordings find nothing, no LoRA is published for that model: say so, offer prompt words for the look (or a model whose LoRAs have it) and stop; never page through the hubs' APIs or web lists yourself, the search already covers Civitai and Hugging Face.
3. **Choose.** Prefer a close match of the theme with real downloads; `open` on a `page_url` (Civitai pages are read through its API) gives the description, versions and trigger words when you need them to decide.
4. **Install.** `lora_install` with the `id` and the same `model_type` downloads it into the model's LoRA folder (the user sees the progress) and returns `usage`: `activated_loras` gets the file name, `loras_multipliers` starts at 1.0 (lower it when the effect overwhelms the picture), and one trigger word goes in the prompt. A file already installed is reported as `exists`. A zip (often the HIGH / LOW pair of a Wan 2.2 LoRA) is unpacked into the folder and `usage` lists every file. WanGP finds installed LoRAs by file name: never download, unzip or copy LoRA files yourself (the LoRA folders are not reachable from the sandbox or wangp_io, and nothing needs copying).
5. **Two-phase models (Wan 2.2 14B).** They generate with a high-noise then a low-noise model, and their LoRAs often come as two files: a result's `other_versions` (or two results) named HIGH and LOW. Install both (unless one zip holds both), list both in `activated_loras` and give each its phase: `loras_multipliers` `"1;0 0;1"` (first file on the high-noise phase only, second on the low-noise phase only). A single-file LoRA for these models takes `"1"` on both phases. Results are ordered with the model's own kind first: prefer a T2V LoRA for a text-to-video model and an I2V one for image-to-video.

In the answer, give each LoRA's name, its page url (the chat makes it a link), its trigger words and how to use it. Civitai downloads need the user's Civitai API key (Configuration > Deepy); say so if the install reports it missing instead of retrying. Adult-rated LoRAs are excluded unless the user asks (`nsfw`); licenses differ (some forbid commercial use): the page url is where the user checks them.
